About

What this is, and how it is made

An index of open RL environments for language-model agents, so that anyone training a model can find a place to practice a skill, see how it is rewarded, and run it.

What counts as an environment

A set of tasks an agent can attempt, with a way to score each attempt. On the Hugging Face Hub an environment is a dataset repository tagged rl-environment, as described in the Hub's RL environments post. The Hub hosts the tasks; a framework such as Harbor, Verifiers, OpenEnv or NeMo Gym supplies the runtime and runs the verifier.

The index holds 396 entries as of 2026-11-23: 322 dataset repositories with that tag, 20 further tasksets from a hand-kept list of terminal and software-engineering environments that do not carry the tag, and 54 live Spaces with the same tag and at least three likes. Several thousand more Spaces carry the tag, most of them entries to one hackathon in spring 2026; they are left out until they attract use. Repositories that carry the tag but hold only trajectories, checkpoints, slides or demos are left out too (9 so far).

Why ISCED-F

Environments need one system of domains that already exists, covers all of human work and study, and is not ours. ISCED-F 2013 is UNESCO's classification of fields of education and training: 11 broad fields, 29 narrow and 80 detailed. Ministries, Eurostat and the OECD already use it to count who studies what. Filing environments in it makes the gaps visible: a field with graduates and no environment is a field models have nowhere to practice.

Each environment gets one detailed field, chosen by the subject of the task and not by the tool. A terminal task about genomics is biology. Where a second field fits, it is recorded and shown on the field page. Some conventions: general shell and operations work is 0612, software development is 0613, using applications as an end user is 0611, data analysis is 0542, text exercises with no subject are 0021, and games are 1015.

How records are made

Downloads, likes, licence, dates and tags come from the Hub API. The summary, field, reward, interface, task count and run command are read from each publisher's card by a language model working to a fixed schema, with instructions to leave a value empty when the card does not state it. Run commands marked "From the card" are copied verbatim. Commands marked "common pattern" are the usual way to run that framework and were not taken from the card.

These records have been spot-checked, not audited line by line, and none of the environments has been run by us. The card is the authority. If a record is wrong, tell us and it will be corrected.
